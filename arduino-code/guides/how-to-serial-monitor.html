How to Serial Monitor

What Serial is, baud matching, IDE and Tinkercad.

What Serial is: a text chat between your sketch and you. The board (or simulator) prints lines; you read them to see what the code thinks is happening — button values, sensor numbers, which mode you are in.

You will need this skill by Module 1 (buttons) and it is required for Module 3 analog work. Learn it here before you need it under pressure.

Guide

1. The two lines of code you will see constantly

Inside setup():

Serial.begin(9600);   // start Serial at 9600 baud

Anywhere you want a message (often inside loop(), with care — see §6):

Serial.println("Hello");     // text + new line
Serial.println(sensorValue); // print a number
PieceMeaning
SerialThe Serial object built into Arduino
begin(9600)Open the channel at 9600 baud
printlnPrint, then move to the next line

Until Serial.begin runs, prints may be missing or weird — always begin in setup().

Guide

2. Baud rate — the matching rule

Baud = speed of the text link. Common course values: 9600 (default habit) or sometimes 115200 (faster; used in some advanced sketches).

Rule: the number in Serial.begin(...) must match the baud dropdown in the Serial Monitor.

SketchMonitor settingResult
Serial.begin(9600)9600Readable text
Serial.begin(9600)115200Garbage characters
Serial.begin(115200)9600Garbage characters

Garbage looks like random symbols — almost always baud mismatch, not a broken board.

Guide

3. Open Serial Monitor in Arduino IDE 2.x

  1. Plug in the board only if you are using hardware (not needed for Verify-only practice).
  2. Select the correct Board and Port (hardware).
  3. Upload your sketch (Serial output comes from the program running on the board).
  4. Open Serial Monitor:

- Toolbar icon that looks like a magnifying glass / monitor, or - Menu Tools → Serial Monitor

  1. At the bottom of the Monitor, set baud to match Serial.begin.
  2. Optional: set line ending to Both NL & CR or Newline if a lesson sends commands to the board; for beginner println debugging, viewing output matters most.

Clear: use the clear / trash control if the window is cluttered. Autoscroll: leave on so new lines stay visible.

Web Editor: look for the Serial Monitor panel after Upload — same baud-matching rule.

Guide

4. Open Serial Monitor in Tinkercad Circuits

  1. Open your circuit’s Code panel (Text mode).
  2. Confirm the sketch calls Serial.begin(9600) (or whatever the lesson uses).
  3. Click Start Simulation.
  4. Find Serial Monitor in the simulation / code UI (often a tab or pane below the code).
  5. Watch lines appear as loop runs.

If nothing prints:

  • Is simulation running (not paused)?
  • Did you call Serial.begin in setup?
  • Are you looking at the Serial pane, not only the 3D circuit view?

Tinkercad does not use a separate USB port — the Monitor is built into the sim UI.

Guide

5. First practice sketch (either IDE or Tinkercad)

void setup() {
  Serial.begin(9600);
  Serial.println("setup done");
}

void loop() {
  Serial.println("loop tick");
  delay(1000);  // temporary — Module 2 teaches better timing
}

Success: you see setup done once, then loop tick about once per second. Garbage: fix baud. Nothing: simulation not started / Monitor not open / Upload failed on hardware.

6. Flooding vs paced prints

HabitWhat you seeFix
Serial.println every loop with no delayThousands of lines; UI freezes; hard to readPrint every 200 ms+ or use a millis timer
delay(200) only to slow printsEasy early on; blocks other workOK for Module 3 sensor measurement labs; prefer millis pacing when Gate A (no blocking) matters
Printing inside tight debounce experimentsCan change timing feelPrint on change or at a slow rate

Beginner pattern (blocking, honest for early analog labs):

int value = analogRead(A0);
Serial.println(value);
delay(200);

Module 2+ pattern (non-blocking idea): remember last print time with millis() and print only when enough time passed — lessons show the full form.

Guide

7. Debug order: Serial before actuators

When a button, mode, or sensor “does nothing”:

  1. Print the raw reading (digitalRead, analogRead, mode variable).
  2. Confirm the number matches your mental model (pull-up pressed = LOW, etc.).
  3. Then drive LEDs or buzzers from that logic.

Guessing by watching only the LED wastes time. Serial tells you what the sketch believes.

8. Common Serial failures

SymptomLikely cause
Weird symbolsBaud mismatch
Blank MonitorMonitor closed; wrong port; sketch never Uploaded; sim paused; forgot Serial.begin
One message then silencePrint only in setup; loop never prints; board reset loop
Flood / frozen windowPrinting every loop without pacing
Works in TC, not IDEPort/board wrong; cable charge-only; need Upload not only Verify

Debugging playbook

Ordered steps when something should work: sim → wiring → pins → Verify → Serial → logic.

How to use this page: Run the steps in order. Change one thing, re-test, then continue. Companion: Symptom tables live in the Troubleshooting FAQ. This playbook is the procedure; the FAQ is the encyclopedia.

You do not need to memorize electronics. You do need a calm order so you stop rewriting the whole sketch for a backwards LED.

Guide

0. Mindset (10 seconds)

  1. The last change is guilty first — wire or code, not both at once.
  2. Prove a simpler circuit — steady LED on pin 13 before bounce, PWM, or libraries.
  3. Prefer evidence — Serial prints beat guessing (digitalRead, analogRead, mode names).

Do not jump to step 6 while step 2 is wrong.

Guide

2. Fast path by milestone

Module 0 — first light

  1. Sim running.
  2. Polarity + resistor + GND.
  3. pinMode + digitalWrite(HIGH) smoke-test (Lesson 0.3 starter).
  4. Only then add Blink timing.

Module 1 — buttons & multi-LED

  1. Each LED path + shared GND rail.
  2. INPUT_PULLUP + button to GND.
  3. Serial.println(digitalRead(buttonPin)) while pressing.
  4. Then edges / debounce — not before the raw reading makes sense.

Module 2 — timing

  1. Can you still read the button with no long delay on the blink path?
  2. Print millis() or a mode name to prove loop is alive.
  3. One timer first; add the second timer only after the first is stable.

Module 3 — analog

  1. Serial stream of analogRead before lamp logic (Lesson 3.2 habit).
  2. Pot ends on 5V and GND, wiper on A0 (or your named Ax).
  3. PWM only on ~ pins; map 0–1023 → 0–255 before analogWrite.
  4. Chatter at a threshold → hysteresis (two thresholds), not a faster loop.

Hardware Upload (Module 6–7)

After the sim playbook:

  1. Data USB cable; correct Board + Port.
  2. Drivers / permissions (CH340, dialout, Gatekeeper) — see FAQ + Lesson 7.1.
  3. Re-check physical polarity and rail jumpers — desk boards do not auto-fix seating.

3. One-change experiments

GoalSmallest experiment
Prove the LED pathForce digitalWrite(ledPin, HIGH); empty loop
Prove the buttonPrint raw digitalRead only — no LED logic
Prove the potPrint analogRead only — no thresholds
Prove non-blockingBlink with millis and print a counter every loop batch
Prove UploadStock Blink on pin 13 before your big sketch

If the tiny experiment fails, do not debug the big sketch yet.

5. Asking a human (last resort)

Send four things:

  1. Which lesson / circuit name.
  2. Which playbook step failed (1–6).
  3. Pin map (e.g. ledPin=9, buttonPin=2, pot on A0).
  4. A few Serial lines or the first Verify error.

That beats “my LED doesn’t work” and gets you unstuck faster.

Getting started

Where to begin, accounts, Tinkercad vs IDE vs hardware, kit timeline.

Who this is for: Absolute beginners — no coding, no Arduino, no electronics coursework. What this page does: Tell you where to begin, in what order, which accounts to create, and when you need Tinkercad vs the Arduino IDE vs real hardware.

Guide

1. Can you take this course?

Yes, if you have:

  • A computer with internet (Windows, macOS, or Linux)
  • Willingness to follow short wiring steps (on screen first)
  • About 3–4 hours for Module 0

You do not need: prior programming, an electronics degree, or a physical board on day one.

Guide

2. Where to start (read this once)

  1. Skim this page and bookmark the guides index.
  2. Skim the short electricity primer (10–15 min) before you wire an LED.
  3. Keep the glossary open in a tab — look up words as they appear.
  4. Begin Module 0 with the Tinkercad-first path below (do not block on IDE install). Day one = open Module 0, then lesson 0.1 What is a microcontroller?.
  5. When something fails, run the debugging playbook, then the troubleshooting FAQ before guessing.

7. Breadboard 101 (30-second mental model)

You will see “breadboard (optional but recommended)” early. Full walkthrough: Breadboard basics. The short version:

  • Rows of 5 holes (usually lettered a–e and f–j) are connected sideways inside the plastic. A wire in hole a3 connects to b3, c3, d3, e3 — same row number, same half of the board.
  • The center gap splits the two halves. a3 does not connect across to f3.
  • Power rails (long +/− strips along the edges) run the length of the board. Put 5V on the + rail and GND on the − rail once, then tap those rails for every part that needs power or ground.
  • Shared GND means every LED cathode, button-to-GND wire, and sensor ground returns to the same GND idea — one rail tied to Uno GND is the usual habit.

ASCII of a single LED path (same idea on a breadboard or direct to the Uno):

Uno pin  →  resistor  →  LED (+) anode  →  LED (−) cathode  →  GND

More electricity vocabulary: electricity primer. When something “should work,” run the debugging playbook before rewriting the sketch.

8. Study habits that prevent “I need a human”

  1. One change at a time — wire or code, not both, when debugging.
  2. Starter first, complete only when stuck — reading the answer early skips the learning.
  3. Text mode in Tinkercad, not Blocks — the course is C++-style sketches.
  4. Serial before guessing — print the button or sensor value; see Serial how-to.
  5. FAQ before forum panic — troubleshooting mirrors the silent failures beginners hit first.
  6. Respect [TC†] callouts — when a lesson says simulation lies (bounce, Wi‑Fi, some sensors), believe it.

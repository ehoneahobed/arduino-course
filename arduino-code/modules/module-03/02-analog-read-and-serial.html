analogRead & Serial.print

Call analogRead, print labeled Serial lines, and scale 0–1023 with map() before you trust any actuator.

About 40 minutes. Serial Monitor required.

Start here

Learning outcomes

  1. Stream analogRead values to the Serial Monitor clearly.
  2. Scale raw 0–1023 with division or map() (e.g. 0–100 or 0–255).
  3. Use Serial as the primary sensor debug tool.
Concept

One sample, many uses

Concept

analogRead(pin) returns an int. Store it, then print, map, and decide with the same sample so debug matches behavior.

int raw = analogRead(potPin);   // 0..1023 typical on Uno
Part

map() scaling

int percent = map(raw, 0, 1023, 0, 100);
int duty    = map(raw, 0, 1023, 0, 255);  // ready for PWM

Integer math truncates. Real pots may not hit exact 0 or 1023 — normal.

Part

Readable Serial

Serial.print("raw=");
Serial.print(raw);
Serial.print("  pct=");
Serial.println(percent);

Pace prints (~100 ms) with a short delay or a millis print timer so you do not flood the Monitor.

Lab

Stream and scale

15 min

Circuit M3-L02-AnalogSerial: pot on A0. Open Serial at 9600. Turn the knob — raw ~0–1023, pct ~0–100. Then map to 0–255 as duty.

Complete shape

void loop() {
  int raw = analogRead(potPin);
  int pct = map(raw, 0, 1023, 0, 100);
  Serial.print("raw="); Serial.print(raw);
  Serial.print("  pct="); Serial.println(pct);
  delay(100);  // or millis print timer
}
Patterns

Serial stream first

Pattern

Print the sensor before fancy outputs. Label columns. Prefer a millis print timer when the sketch must stay interactive.

Check

Check yourself

  1. Why store analogRead in a variable before printing and mapping?
    Model answer

    So print, map, and decide use the same sample.

  2. What does map(raw, 0, 1023, 0, 255) produce?
    Model answer

    A linearly scaled value in roughly 0–255 (PWM-ready).

  3. Why pace Serial prints?
    Model answer

    Flooding makes the Monitor unreadable and can slow the sim.

  4. True or false: a pot may never hit exact 0 or 1023.

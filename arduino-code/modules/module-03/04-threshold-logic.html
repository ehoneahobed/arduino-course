Threshold logic

Turn a lamp on when a reading crosses a setpoint — then add hysteresis so noise near the edge does not chatter.

About 40 minutes.

Start here

Learning outcomes

  1. Switch a load on/off when an analog reading crosses a threshold.
  2. Explain why a single threshold chatters near the edge.
  3. Add hysteresis (separate on and off thresholds).
Concept

Cutoff vs deadband

Concept

A threshold is a cutoff. Near it, tiny wiggles flip the decision every loop — chatter. Hysteresis uses two lines and a remembered state.

// Chatty:
bool lampOn = (raw < threshold);
Part

Two thresholds

raw high (bright) ── offAbove=550 ··· turn OFF when rising past
                         (deadband)
                   ── onBelow=450  ··· turn ON when falling past
raw low (dark)

if (!lampOn && raw < onBelow)  lampOn = true;
if (lampOn  && raw > offAbove) lampOn = false;

Between the lines: keep the previous state.

Lab

Chatter then fix

15 min

Circuit M3-L04-Threshold: pot on A0 (LDR stand-in); LED on 13. Run single-threshold first — rock the slider near mid. Then switch to hysteresis. Serial-print raw and lampOn.

Patterns

Remembered state

Pattern

Keep bool lampOn. Do not assign lampOn = (value < threshold) on noisy signals.

Check

Check yourself

  1. Why does a single threshold chatter?
    Model answer

    Noise near the edge flips the comparison every loop.

  2. In the night-light example, when does the lamp turn on vs off?
    Model answer

    On when falling below onBelow; off when rising above offAbove.

  3. Between the two thresholds you keep the previous state.
  4. Why use Serial while tuning thresholds?
    Model answer

    So you measure dark/bright numbers instead of guessing.

Watch outs

Common mistakes

MistakeFix
onBelow > offAbove for this polarityKeep onBelow < offAbove
No remembered stateUse bool lampOn
Guessing thresholds blindMeasure with Serial first

Resilience pass

Demos that only work when the user is gentle are toys. Harden bounce, hangs, and unclear failures without adding new features.

About 50–70 minutes. Harden the 9.2 slice on the desk.

Start here

Learning outcomes

  1. Upgrade inputs to robust debounce (and note ISR + loop rules if Capstone D).
  2. Add timeouts / software watchdogs so modes cannot hang forever.
  3. Make Serial (or OLED) errors clear when sensors or links fail.
Concept

Harden, don’t feature

Concept

Resilience is product behavior under abuse and failure: mash the button, unplug the sensor, kill Wi‑Fi. Patterns weight is 35% — bounce, timeouts, and honest errors count.

Part

Resilience checklist

  1. Every button / trip edge debounced (or documented ISR + loop debounce)
  2. Alarm / remind / connect modes have a timeout or ack path
  3. Sensor read failures print a clear Serial line (not silent zeros)
  4. Actuators return to SAFE on boot and on known fault paths
  5. IoT (C): reconnect FSM + fail-safe from Module 8 still present
  6. No new MVP stories sneaked in during this pass

Debounce: rising/falling edges with millis quiet window. Timeouts: ALARM auto-mute, REMIND blink budget, WIFI connect window. Errors: DHT_FAIL, I2C_NACK, WIFI_DOWN — not mysterious zeros.

Lab

Abuse the slice

35 min

Mash buttons; unplug/cover sensors; for C kill the AP. Confirm debounce holds, timeouts fire, Serial names the fault, actuators go SAFE. Update the diagram if you add timeout states.

Patterns

Checklist-driven pass

Pattern

One resilience commit (or clearly marked section) separate from features. Fail-safe on fault enter. Clear error vocabulary on Serial.

Check

Check yourself

  1. Name three items on the resilience checklist.
    Model answer

    Any three: debounce, timeouts, clear Serial errors, SAFE actuators, IoT reconnect/fail-safe, no new features.

  2. Why separate resilience from new features?
    Model answer

    So hardening is visible and regressions are easier to spot.

  3. What should a failed DHT read print instead of fake zeros?
    Model answer

    A clear error token / line (e.g. DHT_FAIL) and keep last-good or SAFE policy.

  4. Lesson 9.3 is the right time to add a second sensor and OLED layout.

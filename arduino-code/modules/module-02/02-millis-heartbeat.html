Pattern: millis() heartbeat

Schedule an LED toggle with previousMillis and interval — zero delay() in loop.

About 40 minutes. Tinkercad timing is approximate [TC†].

Hint

When the blink “won’t change”

If timing feels stuck, confirm you are not still using delay on the main path, then walk the Debugging playbook. Print millis() with the Serial Monitor to see the heartbeat advance.

Start here

Learning outcomes

  1. Explain what millis() returns.
  2. Toggle an LED with previousMillis / interval without delay().
  3. Keep loop free for other work between toggles.
Concept

Ask the clock; do not sleep

Concept

millis() returns an unsigned long — ms since start. You ask “has enough time passed since my last action?” and act only when yes.

Pattern

Blink without delay

const unsigned long interval = 500;
unsigned long previousMillis = 0;
bool ledState = false;

void loop() {
  unsigned long currentMillis = millis();
  if (currentMillis - previousMillis >= interval) {
    previousMillis = currentMillis;  // or += interval
    ledState = !ledState;
    digitalWrite(ledPin, ledState ? HIGH : LOW);
  }
}

Prefer current - previous >= interval (overflow-safe) over current >= previous + interval.

Lab

Heartbeat

15 min

Circuit M2-L02-MillisHeartbeat: pin 13 → 220 Ω → LED → GND. Change interval to 200 and 1000 — rate changes with zero delay in loop.

[TC†]: Simulated clock may not match a stopwatch. Trust the pattern; verify absolute timing on hardware.

Patterns

Core non-blocking timer

Pattern

This heartbeat is the core timer for the rest of the course — several timers, one-shots, and debounce all build on it.

Check

Check yourself

  1. What type for millis() values, and why?
    Model answer

    unsigned long — matches millis() and supports wrap-around subtraction.

  2. What does previousMillis remember?
    Model answer

    The timestamp of the last toggle (start of the current interval).

  3. This pattern still uses delay() inside millis().
  4. Why prefer subtract-and-compare over previous + interval?
    Model answer

    Unsigned subtraction stays correct when millis overflows.

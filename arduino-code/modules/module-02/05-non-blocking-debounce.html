Pattern: non-blocking debounce

Upgrade Module 1 debounce: timestamp lockout (or stable-window) with millis() so other timers never freeze.

About 40 minutes.

Start here

Learning outcomes

  1. Replace delay(50) debounce with a millis lockout or stable-window check.
  2. Accept one press → one event while a heartbeat keeps running.
  3. Explain why non-blocking debounce is required once you multi-task.
Concept

Wait without sleeping

Concept

Debounce still ignores chatter. Module 1 slept with delay(40). Module 2 remembers lastAcceptMs and keeps looping.

Part

Lockout (simplest)

// on raw HIGH→LOW edge:
if (now - lastAcceptMs >= debounceMs) {
  lastAcceptMs = now;
  // accept one event
}

Stable-reading (Arduino tutorial style): restart a clock whenever the raw pin changes; accept only after it stays the same for debounceMs.

Do not while (digitalRead == LOW) {} — that still blocks.

Lab

Heartbeat + toggle

18 min

Circuit M2-L05-DebounceMillis: heartbeat 13, toggle 8, button 2. One click → one toggle; heartbeat never stalls; no delay().

Lockout complete

int raw = digitalRead(buttonPin);
if (raw == LOW && lastRaw == HIGH) {
  if (now - lastAcceptMs >= debounceMs) {
    lastAcceptMs = now;
    toggleState = !toggleState;
    digitalWrite(togglePin, toggleState ? HIGH : LOW);
  }
}
lastRaw = raw;
Patterns

Gate A input path

Pattern

Keep debounce even if Tinkercad looks bounce-free — rubric and hardware demand it.

Check

Check yourself

  1. What does non-blocking debounce not do that Lesson 1.5 often did?
    Model answer

    It does not call delay() or spin until release.

  2. What does lastAcceptMs represent in lockout debounce?
    Model answer

    The time the last event was accepted — start of the ignore window.

  3. Why keep a heartbeat LED in this lab?
    Model answer

    To prove other tasks keep running during the debounce window.

  4. while (digitalRead == LOW) {} is OK if blink uses millis.

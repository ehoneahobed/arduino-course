Why delay() blocks the world

Prove that a long delay() freezes buttons — and set the Module 2 goal: keep loop free to check inputs every pass.

About 30 minutes.

Start here

Learning outcomes

  1. Explain why a long delay() makes buttons feel frozen.
  2. Demonstrate a blink-with-delay sketch that ignores a button during the wait.
  3. State the Module 2 design goal: non-blocking timing so inputs stay live.
Concept

Blocking vs cooperative

Concept

delay(ms) tells the Arduino: stop everything and wait. During that wait, loop does not run — so digitalRead does not either. Interactive gadgets need the opposite: check time, do a tiny bit of work, come back soon.

loop starts → LED on → delay(2000) ← asleep → LED off → delay(2000) ← asleep
(button presses during delay are missed or laggy)
Lab

Prove the freeze

12 min

Circuit M2-L01-DelayBlocks:

Pin 13 → 220 Ω → blink LED → GND
Pin 8  → 220 Ω → ack LED → GND
Pin 2  → button → GND (INPUT_PULLUP)

Press during the 2 s waits. The ack LED often only reacts after a delay finishes.

Complete (blocking demo)

void loop() {
  digitalWrite(blinkPin, HIGH); delay(2000);
  digitalWrite(blinkPin, LOW);  delay(2000);
  // Sampled only ~every 4 seconds
  digitalWrite(ackPin, digitalRead(buttonPin) == LOW ? HIGH : LOW);
}
Part

Cooperative loop

  1. Glance at the clock.
  2. Glance at the button.
  3. Update any LED that is due.
  4. Repeat — no multi-second sleep.

Short delay(10) after Serial.begin in setup is fine. Long UI delays on interactive paths are not — Gate A after this module.

Patterns

No long delay on interactive paths

Pattern (awareness)

Module 1 tolerated blocking sequences. Module 2 replaces them. Waiting will be remembered with a timestamp, not sleep.

Check

Check yourself

  1. What does delay(2000) prevent loop from doing?
    Model answer

    Running any other code — including reading buttons and updating other LEDs.

  2. Why does a short button tap get missed in the complete sketch?
    Model answer

    The pin is only checked once per ~4 s cycle; a quick press happens while the board is asleep.

  3. Putting digitalRead before a delay keeps the button responsive during the delay.
  4. What will Module 2 use instead of sleeping?
    Model answer

    millis() timestamps and interval checks (non-blocking timing).

One-shot and repeating timers

Fire a ~200 ms beep (or LED pulse) once after a press, while a repeating heartbeat never stalls.

About 40 minutes.

Start here

Learning outcomes

  1. Distinguish repeating vs one-shot timers.
  2. Trigger a ~200 ms pulse after a press without delay().
  3. Arm / disarm with a boolean flag and a timestamp.
Concept

Not every timer repeats forever

Concept

A one-shot runs for a fixed duration after an event, then turns off. Same millis() — you just clear a flag when done.

KindStops whenExample
RepeatingYou disable itStatus blink
One-shotAfter duration msBuzzer chirp
Pattern

Arm and expire

// On press edge (if !beepActive):
beepActive = true; beepStartedAt = millis();
digitalWrite(buzzerPin, HIGH);

// Every loop:
if (beepActive && (millis() - beepStartedAt >= beepMs)) {
  beepActive = false;
  digitalWrite(buzzerPin, LOW);
}

Ignore-while-active is the simpler retrigger policy for this lesson.

Lab

Heartbeat + chirp

18 min

Circuit M2-L04-OneShot: blink 13, buzzer/LED 11, button 2. Short pulse per press; heartbeat never stalls.

Patterns

Both in one loop

Pattern

Repeating heartbeat + one-shot beep coexist. Both use timestamps; neither sleeps.

Check

Check yourself

  1. What two pieces of data does a one-shot need besides duration?
    Model answer

    A flag (beepActive) and a start timestamp (beepStartedAt).

  2. How does a one-shot differ from a repeating heartbeat?
    Model answer

    Repeating keeps scheduling forever; one-shot runs once then clears until re-armed.

  3. Why check !beepActive before arming again?
    Model answer

    Ignore-while-active — avoids restarting/overlapping chirps.

  4. delay(200) after buzzer HIGH is acceptable in Module 2.
Watch outs

Common mistakes

MistakeFix

Stretch

Retrigger: each press restarts beepStartedAt. Or arm a second 500 ms LED one-shot on the same press.

Build: Remote environment node

Sensor → Wi‑Fi → phone/browser or MQTT broker. Pick Path M or Path H deeply. Local sensing still matters when RF dies.

About 90–120 minutes. ESP32 desk hardware required for Gate D.

Start here

Learning outcomes

  1. Ship a remote environment node: local sensor(s) + optional OLED + MQTT or HTTP + one networked actuator.
  2. Combine Module 8 skills: Wi‑Fi, secrets, HTTP or MQTT, reconnect FSM, rate limits, fail-safe.
  3. Meet Gate D; keep Gates A–C habits.
Brief

Path M or Path H

PathTelemetryActuator
M — MQTTPublish JSON to …/telemetrySubscribe …/cmd/actuator
H — HTTPGET /sensors or periodic POSTGET /actuator?state=on (or POST)

MVP: header with wiring + ASCII diagram + SAFE_LEVEL + topic/URL plan; FSM with WIFI_CONNECTING / ONLINE / RECONNECT_WAIT; non-blocking sample + rate-limited publish; one physical sensor; OLED or Serial UI; actuator obeys network ONLINE and goes fail-safe offline; no passwords in committed .ino; no interactive delay on the main path.

Build

Wire & integrate

60+ min

Project M8-L07-EnvNode. Typical map (verify your DevKit): DHT on GPIO 4; actuator LED GPIO 2 or external + 220 Ω; OLED on default I²C (scan address); relay via driver module — never coil direct. Draw states first. JSON shape: {"temp_c":…,"humidity":…,"state":"ONLINE","ts_ms":…}.

Honesty

[ESP] [HW] only for Gate D. Tinkercad is not accepted for the networking proof. Serial-only fake without RF is prep, not credit.

Demo

Demo checklist

  1. Serial boot + IP (or MQTT connected)
  2. Telemetry visible remotely
  3. Actuator toggles from the network
  4. AP off → fail-safe + samples continue
  5. AP on → recovers to ONLINE
Patterns

Spine stack

Pattern

secrets.h (8.2/8.6) + net FSM (8.5) + HTTP or MQTT (8.3/8.4) + rate limit + fail-safe + optional OLED wrappers. Module 9 polishes capstones; deeper TLS/fleet → future esp32/.

Check

Check yourself

  1. Which gate does a reachable telemetry path prove?
    Model answer

    Gate D.

  2. What must the actuator do when Wi‑Fi drops?
    Model answer

    Go to fail-safe (SAFE_LEVEL).

  3. Why is a Serial-only fake without RF insufficient for this spine?
    Model answer

    Gate D needs a device reachable over Wi‑Fi with real telemetry.

  4. Finishing 8.7 means you should remove the planned esp32/ course from the catalogue.

Wi‑Fi connect sketch

Station mode joins an AP you control. Keep SSID/password out of shared repos. Serial tells the truth about join, IP, and disconnect.

About 45 minutes. Not TC — real ESP32 + 2.4 GHz AP required.

Start here

Learning outcomes

  1. Join a 2.4 GHz AP, print the IP, detect disconnect.
  2. Keep credentials out of repos with local secrets.h + .gitignore.
  3. Sketch connect / wait / online / retry that does not pretend Tinkercad substitutes for RF.
Concept

Associate, DHCP, timeout

Concept

WiFi.begin(ssid, pass) starts association; wait (with timeout) until WL_CONNECTED, then read WiFi.localIP(). Radios fail — detect loss and retry (full FSM in 8.5).

Part

secrets.h layout

Project ships secrets.h.example with placeholders; your machine holds real secrets.h (gitignored). Sketch #include "secrets.h" — never paste passwords into the committed .ino.

#pragma once
#define WIFI_SSID     "your-ssid"
#define WIFI_PASSWORD "your-password"
Lab

Join and print IP

25 min

Project M8-L02-WifiConnect. Create secrets.h; upload starter; upgrade to complete (timeout, RSSI, disconnect notice). Briefly leave range — note status for 8.5.

Patterns

Timeout, don’t spin forever

Pattern

secrets.h + gitignore. Cap join attempts; print why you gave up. Serial: boot → attempting → IP or fail. Silent Serial → fix USB before blaming the AP.

Check

Check yourself

  1. Why prefer secrets.h over typing the password in the .ino?
    Model answer

    Avoid leaking credentials into shared repos / screenshots.

  2. What band limitation bites classroom labs most often?
    Model answer

    5 GHz–only APs — use 2.4 GHz.

  3. What does a successful join print that proves DHCP worked?
    Model answer

    A valid WiFi.localIP() (LAN address).

  4. Tinkercad is an acceptable substitute for this lesson’s RF path.

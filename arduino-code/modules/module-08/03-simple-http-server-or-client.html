Simple HTTP server or client

Pick one path deeply: serve sensor JSON from the board, or POST to a webhook. One telemetry path toward Gate D — MQTT comes next.

About 50 minutes. Desk ESP32 on Wi‑Fi; same LAN for Path S.

Start here

Learning outcomes

  1. Explain HTTP as request → response (methods, status, simple JSON).
  2. Implement one path: onboard HTTP server or HTTP client POST.
  3. Confirm telemetry from a phone/browser or webhook without MQTT yet.
Concept

Server vs client on the LAN

Concept

A server on the ESP32 listens (port 80); your phone is the client. Or the ESP32 is the client and POSTs to a remote URL. Same LAN first — guest APs often isolate clients.

Part

Lab

One HTTP telemetry path

30 min

Project M8-L03-Http — pick S or C. Reuse secrets.h; add webhook URL for Path C. Starter → complete. Capture proof: browser screenshot or webhook body.

Patterns

Ship one path deeply

Pattern

JSON as struct printout (Module 4 packet thinking). Keep loop alive — no buried delay(10000) around network calls (8.5 deepens this).

Check

Check yourself

  1. What must be true of phone and ESP32 for Path S on a home AP?
    Model answer

    Same LAN (and no client isolation).

  2. Which loop call keeps a WebServer responsive?
    Model answer

    server.handleClient().

  3. Why put webhook URLs in secrets.h?
    Model answer

    URLs can embed tokens — treat like passwords.

  4. Gate D requires both HTTP and MQTT.

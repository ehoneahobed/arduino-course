Loops: for and while

Use for for counted LED chasers and while to wait until a button — and know both can block.

About 40 minutes. LEDs on 8/9/10 + button on 2.

Start here

Learning outcomes

  1. Use a for loop to sequence an LED chaser without copy-paste.
  2. Use a while loop to wait until a button is pressed (and know it blocks).
  3. Choose for vs while for counted repetition vs “until condition.”
Concept

Extra loops inside loop()

Concept

Arduino already has outer loop(). Inside it, for and while add repetition and waiting — and with delay they block.

Part

for — counted repetition

You can chase three named pins without arrays (digitalWrite(redPin…) three times). Optional shortcut:

const int ledPins[3] = {8, 9, 10};
for (int i = 0; i < 3; i++) {
  digitalWrite(ledPins[i], HIGH);
  delay(200);
  digitalWrite(ledPins[i], LOW);
}
Mini-primer (optional)

An array is a numbered list: ledPins[0] is pin 8, ledPins[1] is 9, ledPins[2] is 10. Module 3 deepens arrays for samples — here it is only a tidy chaser.

Part

while — until condition

while (digitalRead(buttonPin) == HIGH) {
  // wait while NOT pressed (PULLUP)
}

During that while, nothing else runs. Module 2 teaches non-blocking waits.

Lab

Chase, then wait

15 min

Circuit M1-L06-Loops: chase red → yellow → green, then wait for press/release before the next pass.

Complete shape

void chaseForward() {
  for (int i = 0; i < 3; i++) {
    digitalWrite(ledPins[i], HIGH); delay(stepMs);
    digitalWrite(ledPins[i], LOW);
  }
}
void waitForPressAndRelease() {
  while (digitalRead(buttonPin) == HIGH) {}
  delay(40);
  while (digitalRead(buttonPin) == LOW) {}
  delay(40);
}
void loop() {
  chaseForward();
  waitForPressAndRelease();
}
Patterns

for vs while

Pattern

for for counted sequences; while for “until.” Blocking waits are OK for demos — keep the spine responsive with short sequences and debounced edges.

Check

Check yourself

  1. How many times does for (int i = 0; i < 3; i++) run its body?
  2. Difference between Arduino’s loop() and a while inside it?
    Model answer

    loop() is the framework’s forever cycle; while is your own extra repeating block.

  3. Why can a while waiting for a button freeze other LEDs?
    Model answer

    Execution is stuck in that while — nothing else runs.

  4. When is for a better fit than while?
    Model answer

    When you know how many repetitions you want (counted sequence).

Watch outs

Common mistakes

MistakeFix
i <= 3 on a 3-LED arrayUse i < 3
Wrong polarity in whilePULLUP: wait HIGH for “not pressed”
Infinite while (true)Exit conditions; prefer short waits
Stretch

Reverse chaser (i from 2 down to 0) after forward, then wait for the button.

Pattern: contact bounce

Contact bounce: why a single press can look like many presses in software — and why Tinkercad under-models it.

About 30 minutes. Hardware makes bounce clearer; simulation may look too clean.

Start here

Learning outcomes

  1. Describe contact bounce.
  2. Observe (or prepare for) multiple false edges with a naïve press counter.
  3. Explain why Tinkercad under-models bounce and why hardware still needs debounce.
Concept

Metal contacts chatter

Concept

For a few milliseconds contacts make-break-make before settling. Your loop is fast enough to see that as extra presses.

Ideal:  ----________----
Real:   ----_‾_‾___‾_----   (several edges in ~1–20 ms)
Part

Edge vs level

  • Level: “Is the button down right now?” (Lesson 1.3)
  • Edge: “Did it just become pressed?” (counting, toggling)

Bounce hurts edge detection hardest.

Lab

Naïve press counter

12 min

Circuit M1-L04-Bounce. Open Serial. Click once. On hardware one click often adds 2–10 counts.

Complete naïve edge detector

int lastReading = HIGH, pressCount = 0;
void loop() {
  int reading = digitalRead(buttonPin);
  if (reading == LOW && lastReading == HIGH) {
    pressCount = pressCount + 1;
    Serial.println(pressCount);
  }
  lastReading = reading;
}

[TC†]: Simulation may count 1:1. Trust the explanation; verify on hardware when you can.

Patterns

Recognize the failure

Pattern (awareness)

Before debounce code (1.5), recognize: one human press → many software edges. Otherwise debounce feels like superstition.

Check

Check yourself

  1. What is contact bounce in one sentence?
    Model answer

    Mechanical contacts chatter for milliseconds, creating extra edges.

  2. Why do edge counters suffer more than “LED while held” sketches?
    Model answer

    They react to every transition; bounce is extra transitions.

  3. Why is this lesson tagged [TC†]?
    Model answer

    Simulation often under-models bounce — concept still required.

  4. If Tinkercad counts perfectly, you can skip debounce forever.

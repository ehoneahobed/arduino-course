Build: Crosswalk / quiz buzzer

Module 1 project spine: combine multiple LEDs, debounced buttons, and helpers into a crosswalk signal or two-player quiz buzzer.

About 55 minutes. Pick Option A or B (or both).

Start here

Learning outcomes

  1. Combine multiple LEDs, 1–2 debounced buttons, and helpers into one appliance.
  2. Implement a crosswalk or quiz buzzer.
  3. Document wiring, polarity, and behavior in the sketch header.
Brief

Choose a path

Done looks like

A human can use the gadget without Serial; code uses named pins, debounce, and helpers; header lists wiring.

If bounce is invisible in Tinkercad ([TC†] from Lesson 1.4), still keep debounce in the code — required for the rubric and for hardware. Stuck? Troubleshooting FAQ.

Option A — Pedestrian crosswalk

  1. Idle: car green + ped don’t-walk (red).
  2. Debounced walk button → car yellow → car red + ped walk → idle.
  3. Extra presses during the sequence may be ignored.

Option B — Two-player quiz buzzer

  1. First debounced press locks out the other; winner LED on.
  2. Reset button (or similar) clears for the next question.
Wire

Suggested pins

Crosswalk: car 8/9/10, ped 6/7, walk button 2 (INPUT_PULLUP). Name M1-L08-Crosswalk.

Quiz: P1/P2 LEDs 8/9, buttons 2/3, reset 4. Name M1-L08-QuizBuzzer.

Write the story on paper first: idle → event → sequence → return.

Build

Crosswalk complete shape

25 min

Option A — helpers + debounced edge

void showIdle() {
  allCarOff(); allPedOff();
  digitalWrite(carGreenPin, HIGH);
  digitalWrite(pedRedPin, HIGH);
}
void runWalkSequence() {
  allCarOff(); digitalWrite(carYellowPin, HIGH); delay(600);
  allCarOff(); digitalWrite(carRedPin, HIGH);
  allPedOff(); digitalWrite(pedGreenPin, HIGH); delay(3500);
  allPedOff(); digitalWrite(pedRedPin, HIGH); delay(500);
}
// loop: on debounced walk press → runWalkSequence(); showIdle();

Quiz option: separate lastReading per button; lockWinner + clearBoard. Keep debounce even if Tinkercad looks clean.

Your turn: personalize the header — not Ada’s example name.

Deliverable

Checklist

  • Clear interactive behavior in sim or on hardware
  • All pins use const int names
  • Button edges used as events are debounced
  • At least two helpers
  • Header: name, option A/B, pin map, resistor, pull-up polarity
  • Mash-testing does not multi-trigger wildly
Patterns

Integrate Module 1

Pattern

Named pins · debounce on every event edge · one-job helpers · header docs. delay in sequences is still OK — Module 2 makes timing non-blocking.

Check

Check yourself

  1. Which Module 1 patterns did you use on purpose?
    Model answer

    Named pins, debounce, helpers / branching (and loops if used).

  2. What happens if you skip debounce on walk / quiz buttons?
    Model answer

    Double starts, unfair quiz lockouts, flaky counts.

  3. Why are helpers valuable once sequences grow past ~15 lines?
    Model answer

    Readable loop, reuse, easier debugging.

  4. What will Module 2 improve about long delay in sequences?
    Model answer

    Non-blocking timing so inputs can be monitored during animations.

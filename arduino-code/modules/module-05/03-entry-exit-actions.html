Entry / exit actions

Entry runs once when you arrive (start the stopwatch). Exit runs once when you leave (silence the buzzer). Do-while-in-state work stays in the case.

About 40 minutes.

Start here

Learning outcomes

  1. Run entry actions once when entering a state (timer stamps, counters, initial outputs).
  2. Optionally run exit actions once when leaving (stop beep, clear latch).
  3. Avoid re-arming timers every loop pass while staying in the same state.
Concept

The bug entry fixes

Concept

Stamping runStarted = millis() at the top of case RUN every pass means the timeout never fires. Stamp on entry only.

Part

setState hooks

void setState(State next) {
  if (next == state) return;   // idempotent
  exitState(state);
  state = next;
  enterState(state);
}

Lab

COUNTDOWN with clean exit

15 min

Circuit M5-L03-EntryExit: LED→9, buzzer→5, button→2. States IDLE / COUNTDOWN / ALARM. Enter COUNTDOWN stamps timer; after 3 s → ALARM (LED+buzzer); exit ALARM silences buzzer. Serial shows paired exit/enter lines.

Enter shape

case COUNTDOWN:
  stageStarted = millis();
  blinkStamp = millis();
  digitalWrite(ledPin, LOW);
  break;
case ALARM:
  digitalWrite(ledPin, HIGH);
  digitalWrite(buzzerPin, HIGH);
  break;
Patterns

Enter / exit inside setState

Pattern

Timers and “initial LED pattern” in enterState. “Turn buzzer off” in exitState. Calling setState(RUN) while already RUN does nothing.

Check

Check yourself

  1. Why must stageStarted = millis() live in enterState, not every case pass?
    Model answer

    Otherwise the timer restarts every pass and the timeout never fires.

  2. What is a good exit action when leaving ALARM?
    Model answer

    Turn the buzzer (and alarm outputs) off so silence is guaranteed.

  3. What should setState do if next == state?
    Model answer

    Return immediately — no exit/enter.

  4. Entry actions replace the need for millis blinking inside the state.

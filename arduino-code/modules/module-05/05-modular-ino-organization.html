Modular .ino organization

A sketch that works can still be unreadable. Put diagram, pins, events, and FSM in predictable places. loop only orchestrates.

About 40 minutes. Tinkercad uses section banners; desktop IDE may use tabs.

Start here

Learning outcomes

  1. Organize a multi-state sketch into clear sections (pins, types, events, FSM, outputs).
  2. Document the state diagram in comments so Gate B reviewers can find it.
  3. Optionally split helpers into Arduino IDE tabs without breaking Compile.
Concept

Header = contract

Concept

If the diagram is missing from the sketch, it is not Gate-B ready. Full .h/.cpp waits for Module 9 — today is structure discipline.

/*
 * State diagram:
 *   IDLE --START--> RUN --TIMEOUT--> DONE --ACK--> IDLE
 *                    |
 *                    +--CANCEL--> IDLE
 * Wiring: Start D2, Cancel D3; LED D9
 */
Part

Thin loop + sections

void loop() {
  unsigned long now = millis();
  Event ev = collectEvents(now);
  handleFsm(ev, now);
}

Suggested order: header → pins → enums → constants → setup/loop → enter/exit → events → outputs. Optional IDE tabs: main + fsm.ino + events.ino (keep enums in the main/early tab).

Lab

Refactor 5.4

15 min

Take Lesson 5.4 complete (or starter). Add full diagram + wiring header; // ===== banners; make loop ≤ ~15 lines via handleFsm. Success: find “CANCEL in RUN” in under 30 seconds.

Patterns

Sectioned .ino (+ optional tabs)

Pattern

Always section a single file. Add tabs when long. loop: ev = collect…(); handleFsm(ev);

Check

Check yourself

  1. What must appear in the sketch header for Gate B?
    Model answer

    The state diagram (and wiring).

  2. Why keep loop thin?
    Model answer

    Orchestration stays obvious; details live in named helpers.

  3. Tinkercad requires multiple IDE tabs to organize an FSM.
  4. Where should shared enum types live in multi-tab sketches?
    Model answer

    In the main / early tab so all tabs see the types when concatenated.

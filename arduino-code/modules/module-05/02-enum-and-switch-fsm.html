Pattern: enum + switch FSM

The standard beginner FSM on Arduino: named enum values, one switch (state), and a small setState that logs transitions.

About 45 minutes. Keep your 5.1 diagram beside the code.

Start here

Learning outcomes

  1. Declare an enum of device states and hold the current state in one variable.
  2. Implement an FSM with switch (state) and clear transition helpers.
  3. Print readable state names so Serial is a live state-trace debugger.
Concept

Named integers, one switch

Concept

An enum gives typed names instead of magic 0/1/2. A switch picks the block for the current value — one place per state’s behavior.

enum State { IDLE, RUN, ALARM };
State state = IDLE;
Part

Skeleton + transition table

void setState(State next) {
  if (next == state) return;
  state = next;
  Serial.println(stateName(state));
}
switch (state) {
  case IDLE:  /* wait for start */ break;
  case RUN:   /* blink; watch timeout */ break;
  case ALARM: /* solid; wait for ack */ break;
}

Lab

enum + switch

18 min

Circuit M5-L02-EnumSwitch: LED→9, button→2. IDLE→press→RUN (blink)→4 s→ALARM (solid)→press→IDLE; cancel from RUN→IDLE.

Case shape

case RUN:
  // millis blink
  if (now - runStarted >= runMs) setState(ALARM);
  else if (pressed) setState(IDLE);  // cancel
  break;
Patterns

enum + switch FSM

Pattern

enum → State state = IDLE → switch per loop → transitions via setState. Never sprinkle if (state == 2) once you have names.

Check

Check yourself

  1. Why prefer enum State over int with // 0=idle?
    Model answer

    Named, typed values — fewer magic numbers; easier Serial and reviews.

  2. What does break; do at the end of a case?
    Model answer

    Prevents fall-through into the next case.

  3. Where should most transitions be decided?
    Model answer

    Inside the current state’s case (or a transition-table helper).

  4. Every button press must change state in every state.

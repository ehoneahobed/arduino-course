Spaghetti vs states

A state is the named situation the device is in right now. One currentState beats a pile of contradicting bool flags. Draw the diagram before you refactor.

About 40 minutes. Paper / header diagram required.

Start here

Learning outcomes

  1. Spot spaghetti mode logic — tangled if / flag chains that forget transitions or leave outputs stuck.
  2. Refactor a messy multi-mode sketch into named states with one clear current-state variable.
  3. Draw a state diagram first (circles = states, arrows = transitions) before changing code.
Concept

Flags fight; one state does not

Concept

Spaghetti tracks modes with scattered booleans (running, alarm, paused) that can all be true at once. Named states make mutually exclusive modes explicit.

// Painful — flags can disagree
bool running = false; bool alarm = false; bool paused = false;

// Better — exactly one mode
enum Mode { IDLE, RUN, PAUSE, ALARM };  // full enum in 5.2
Mode mode = IDLE;
Part

Diagram before code

        start                 timeout
  IDLE --------► RUN --------------------► ALARM
   ▲              │                           │
   │              │ cancel                    │ ack
   └──────────── PAUSE ◄──────────────────────┘
RuleWhy
Every circle has a nameMatches code identifiers

Lab

See the mess, then name states

18 min

Circuit M5-L01-Spaghetti: LED→9, button→2 (INPUT_PULLUP). Run the messy starter; mash the button. Draw IDLE / RUN / ALARM. Refactor to one state variable; print the name on change.

Named-state shape

if (state == ST_IDLE) {
  if (pressed) enterState(ST_RUN);
} else if (state == ST_RUN) {
  // blink with millis; timeout → ALARM; press → ALARM
} else if (state == ST_ALARM) {
  if (pressed) enterState(ST_IDLE);
}

Gate A still applies — no interactive delay for “debounce.”

Patterns

Diagram before code

Pattern

If you cannot draw it, you do not understand the appliance yet. Prefer one state variable over overlapping booleans for mutually exclusive modes.

Check

Check yourself

  1. What goes wrong when several bools all mean “what mode am I in?”
    Model answer

    Flags can contradict or leave stale true values — undefined combined behavior.

  2. What should you draw before refactoring spaghetti?
    Model answer

    A state diagram — states plus labeled transitions.

  3. Can the device be in RUN and ALARM at once with one state variable?
    Model answer

    No — one variable holds exactly one value.

  4. Module 5 allows long delay() because FSM is different.

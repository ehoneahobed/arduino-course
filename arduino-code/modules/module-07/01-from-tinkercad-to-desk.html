From Tinkercad to desk

The sketch API is the same. The desk adds USB ports, charge-only cables, real bounce, and LEDs that look different. Re-wire a circuit you already understand before adding new sensors.

About 45 minutes. No Tinkercad lab path — diagram reference only.

Start here

Learning outcomes

  1. Rebuild blink + button on a breadboard; choose Board and Port; Upload.
  2. Compare sim vs desk behavior (bounce, brightness, baud) in a short note.
  3. Use a repeatable upload checklist instead of panic.
Concept

Same API, new failure modes

Concept

Board must match silicon; Port must match the cable that just plugged in. Verify compiles; Upload needs both correct. Serial at matching baud is your first proof of life.

PartConnection
LED anodePin 9 via 220 Ω
LED cathodeGND
ButtonPin 2 to GND (INPUT_PULLUP)
Part

IDE upload checklist

  1. Data-capable USB cable, seated firmly
  2. Tools → Board → Uno (or compatible)
  3. Tools → Port → new COM/tty on plug-in
  4. Verify, then Upload → “Done uploading”
  5. Serial Monitor at matching baud (9600)
  6. If fail: unplug/replug, other cable/port, close port lockers, check CH340 drivers
Lab

Desk parity

20 min

Project M7-L01-DeskParity. Upload starter; confirm boot banner. Note bounce multi-fires. Move to complete (non-blocking debounce + millis heartbeat). Comment 2–3 sim-vs-desk differences.

Patterns

Same circuit, two worlds

Pattern

Isolate upload/wiring bugs from new-API bugs. Run the checklist top-to-bottom before rewriting code. Serial as truth.

Check

Check yourself

  1. What two IDE settings must be correct for Upload (not just Verify)?
    Model answer

    Board and Port.

  2. Why might a Tinkercad sketch print multiple lines per click on the desk?
    Model answer

    Real contact bounce (and/or no debounce).

  3. Name three items on the upload checklist.
    Model answer

    Any three: data cable, Board, Port, Verify, Upload, Serial baud, unplug/replug, close port lockers.

  4. A charge-only USB cable is fine for Arduino Upload.

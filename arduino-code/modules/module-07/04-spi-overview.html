SPI overview (light touch)

SPI is usually four wires: SCK, MOSI, MISO, and per-device CS. I²C picks by address; SPI picks by pulling CS LOW.

About 35 minutes. Enough to recognize SD/TFT modules — not a deep file-system course.

Start here

Learning outcomes

  1. Contrast SPI with I²C: wires, speed mindset, typical hobby uses.
  2. Name MOSI, MISO, SCK, CS and explain why each device needs its own chip select.
  3. Run a light lab: SD CardInfo or a documented SPI pin cheat-sheet sketch.
Concept

I²C vs SPI

Concept

Shared data/clock lines, private CS. Only one CS LOW while talking. I²C remains the default for Module 6–7 displays.

Lab

Pinmap or SD

15 min

Project M7-L04-SpiOverview. Fill the pin table in the header. With SD: often CS=4, Example CardInfo. Without: MODE_PINMAP prints cheat-sheet and toggles two “virtual CS” LEDs.

Patterns

Map pins before coding

Pattern

Module label → Uno pin table. One CS per device. Library Examples first, then merge.

Check

Check yourself

  1. Which SPI pin selects which device is listening?
    Model answer

    CS / chip select (typically active LOW).

  2. Name the four classic Uno hardware SPI pin numbers.
    Model answer

    10, 11, 12, 13 (SS, MOSI, MISO, SCK).

  3. One reason to choose I²C over SPI for a small OLED?
    Model answer

    Fewer wires / addressable bus / Module 6 libraries already I²C.

  4. Two SPI devices can share MOSI/MISO/SCK if each has its own CS.

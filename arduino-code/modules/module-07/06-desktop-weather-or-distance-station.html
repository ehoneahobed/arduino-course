Build: Desktop weather / distance station

Spine build: a local multi-sensor station — weather (DHT + display) or distance (ultrasonic + display) — with non-blocking timing and an FSM. No Wi‑Fi yet.

About 75–90 minutes. Gates A + B + C.

Start here

Learning outcomes

  1. Build a physical weather-style or distance-style station with millis timing and an FSM.
  2. Apply desk wiring, power/GND hygiene, I²C scan address, datasheet pin plan.
  3. Meet Gate C (physical upload + real sensor reading); keep Gates A and B.
Brief

Paths

PathSensorsCore states
W — WeatherDHT + displayBOOT → RUN → ALERT → HOLD
D — DistanceHC-SR04 + displayBOOT → RUN → ALERT → HOLD

Done: runs on the desk; mode changes visible; alert clears/holds predictably; I²C address matches your scan; power stays stable.

Wire

M7-L06-Weather or Distance

W: DHT data→4; button→2; alert LED→9; OLED/LCD I²C from scan. D: TRIG→7, ECHO→6; same button/LED/display.

BOOT --ok--> RUN --past threshold--> ALERT
              ^                         |
              +-------- button ack -----+
              +-- long / 2nd btn --> HOLD --btn--> RUN
Build

Sample without freezing

35 min

Shape

const unsigned long sampleMs = 2000;  // DHT prefers polite rates
const unsigned long uiMs = 250;
const float alertTempC = 28.0;   // Path W
const long  alertCm    = 30;     // Path D — closer → ALERT
// millis sample + UI; button → HOLD / ack ALERT
showStatus(stateName(state), value);  // glass or Serial fallback

Header: wiring + datasheet pin plan + ASCII diagram. Prefer glass; document USE_SERIAL_UI only if glass failed.

Deliverable

Checklist

  • Header: wiring, datasheet pin plan, state diagram
  • FSM with BOOT, RUN, ALERT (+ HOLD/ack)
  • Non-blocking sample + UI; display shows state + live value
  • Physical sensor reading demonstrated (Gate C)
  • No interactive delay() on the main path
Patterns

Stack

Pattern

Datasheet pins · I²C scan address · common GND · enum FSM · millis sample/UI · debounced button · display wrappers. Local only — networking is Module 8.

Check

Check yourself

  1. Which gates does this spine prove?
    Model answer

    A non-blocking, B FSM + diagram, C physical upload + real sensor read.

  2. Why scan I²C before hard-coding 0x3C?
    Model answer

    Address may be 0x3D / backpack 0x27 — scan is truth.

  3. What belongs in the sketch header?
    Model answer

    State diagram, wiring, datasheet pin plan, addresses.

  4. Module 7’s station must publish MQTT.

I²C scan & multiple devices

Many devices share SDA and SCL. Each needs a unique address. Scan before blaming the library.

About 45 minutes. HW required.

Start here

Learning outcomes

  1. Explain SDA, SCL, address, shared bus, and why pull-ups matter.
  2. Run an I²C scanner and interpret printed addresses.
  3. Wire and talk to two I²C peripherals safely (unique addresses, common GND).
Concept

Multi-drop bus

Concept

Idle lines held HIGH by pull-ups (often onboard). Missing pull-ups or 5 V/3.3 V fights cause empty scans. Two devices must not share an address.

Part

Scanner idea

#include <Wire.h>
Wire.begin();
for (uint8_t addr = 1; addr < 127; addr++) {
  Wire.beginTransmission(addr);
  if (Wire.endTransmission() == 0) {
    Serial.print(F("Found 0x"));
    Serial.println(addr, HEX);
  }
}

endTransmission() == 0 means a device ACKed. Two devices: same SDA/SCL/GND; construct each library with the scanned address; rate-limit UI updates.

Lab

One device, then two

20 min

Project M7-L03-I2CScan. Scan Device A; add Device B; confirm two distinct addresses. Complete: scan on boot, then init both. Comment addresses in the header.

Patterns

Scan before library blame

Pattern

Empty screen? Scan first. One Wire.begin(), many devices. Thin wrappers so the 7.6 FSM never spreads raw bus calls.

Check

Check yourself

  1. What do SDA and SCL mean in plain language?
    Model answer

    Data line and clock line.

  2. Why run a scanner before changing OLED library code?
    Model answer

    Confirms wiring/power/address — avoids debugging the wrong layer.

  3. Can two devices share address 0x3C on one bus?
    Model answer

    No — addresses must be unique.

  4. Each I²C device needs its own pair of SDA/SCL pins on the Uno.

Polling limits

Polling asks “is the pin HIGH/LOW right now?” each loop. If loop is busy, a short pulse can finish between two reads — your sketch never saw it.

About 40 minutes. Measure the miss before reaching for interrupts.

Start here

Learning outcomes

  1. Explain polling and when loop latency can miss short pulses or edges.
  2. Demonstrate a busy sketch that drops presses, then a lean loop that catches them.
  3. Motivate interrupts when events are rare, short, or must not wait for other code.
Concept

Ask now — or miss forever

Concept

An interrupt is hardware that pauses normal code the instant an edge happens, so the event is latched even when loop is busy. First: prove polling can fail.

void loop() {
  bool pressed = (digitalRead(btnPin) == LOW);
  if (pressed && !wasPressed) count++;
  wasPressed = pressed;
  // ... lots of other work ...
}
Part

Latency budget

If loop often takes…And the pulse lasts…Risk
< 1 msButton held 50–200 msLow
50–200 msQuick tap ~30–80 msMedium — missed edges
500 ms+ (delay, slow I²C)Any short pulseHigh

Before interrupts: make loop fast. Interrupts help when you still cannot guarantee a short loop (or the pulse is microseconds long).

Lab

Miss, then recover

15 min

Circuit M6-L01-PollingLimits: button→2, optional LED→9. Run the busy starter (delay(250+) waste). Click 10 times quickly — compare human vs Serial. Remove the waste; counts should match.

Anti-pattern (teaching only)

// edge logic...
delay(300);           // pretend: slow sensor + display
Serial.println(count);
Patterns

Measure first

Pattern

Count presses while doing heavy work; if Serial ≠ clicks, polling latency is the suspect. Then either keep loop short or use an ISR flag (6.2–6.3).

Check

Check yourself

  1. What is polling in one sentence?
    Model answer

    Repeatedly reading an input inside loop to see its current level.

  2. Why can a short pulse disappear even with “correct” edge code?
    Model answer

    The pulse can finish between two reads while loop is busy.

  3. Name two ways to reduce missed edges without interrupts.
    Model answer

    Shorten loop (no delay, rate-limit Serial); poll more often / avoid blocking on the hot path.

  4. Interrupts replace the need for debounce.

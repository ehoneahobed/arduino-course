Build: Lap counter or reaction timer

Spine build: a lap counter or reaction timer — robust edges, optional ISR, display (or Serial), FSM for ready/go/foul. Pick one path.

About 60–75 minutes. Gate A + Gate B.

Start here

Learning outcomes

  1. Build a lap counter or reaction timer with interrupt/edge detect, debounce, display, and FSM.
  2. Keep ISRs tiny with volatile flags; timing and UX in loop with millis.
  3. Document wiring, state diagram, TC†/HW path, and pin/address choices.
Brief

Paths

PathCore states (minimum)
L — LapIDLE → ARMED → TIMING → SHOW
R — ReactionIDLE → READY → WAIT → GO → RESULT + FOUL

Done: playable from display/Serial; foul/lap rules match the diagram; ISR (if used) only sets flags; zero interactive delay.

Wire

M6-L06-Lap or Reaction

Primary button on 2 (INT0). Reset/arm on 3. Status LED→9; foul LED→8 (Path R). OLED/LCD on SDA/SCL — or USE_SERIAL_UI.

// Reaction (required FOUL on early press):
IDLE --arm--> READY --random wait--> GO --press--> RESULT
               |                      ^
               +--press too soon------→ FOUL --ack--> IDLE
Build

Stack the module

30 min

Shape

// optional: attachInterrupt → volatile pressedFlag
if (consumePress()) { /* feed FSM — not raw edges */ }
// enter GO: goEnteredAt = millis();
// RESULT: reactionMs = millis() - goEnteredAt;
showStatus(stateName(state), value);  // OLED or Serial

Path L: show lap count + last lap ms. Path R: random wait 1.5–4 s before GO; press in READY/WAIT → FOUL.

Deliverable

Checklist

  • Explicit enum + diagram in header
  • Robust debounce on primary input (ISR optional on HW)
  • Non-blocking timing; display or Serial shows mode + number
  • Path R: FOUL on early press; Path L: lap count + last ms
  • Clear re-arm / idle path; no interactive delay
Patterns

Stack

Pattern

Gate B diagram · enum FSM · consumePress debounce · optional ISR+volatile · display wrappers · Gate A millis.

Check

Check yourself

  1. What must the ISR not do in this build?
    Model answer

    Heavy work — Serial storms, display I²C, long logic (only flag / minimal stamp).

  2. How does Path R detect a foul?
    Model answer

    Press while in READY or WAIT (before GO) → FOUL.

  3. Why keep debounce in loop even with USE_ISR?
    Model answer

    Mechanical bounce still multi-fires; stable-window accepts one logical press.

  4. Serial stand-in fails the spine if FSM and timing are complete.

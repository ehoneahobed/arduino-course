Pattern: external interrupts

Hardware pauses normal code on a chosen edge, runs a short ISR, then resumes. On classic Uno, only pins 2 and 3.

About 45 minutes. Expect bounce multi-counts until 6.4.

Start here

Learning outcomes

  1. Use attachInterrupt on an interrupt-capable pin for an edge-triggered counter.
  2. Keep the ISR tiny — flag or increment; no Serial, no delay, no heavy work.
  3. State Uno pin rules and choose FALLING / RISING / CHANGE for pull-up wiring.
Concept

INT0 / INT1

Concept

With button to GND and pull-up, a press is usually FALLING. Always use digitalPinToInterrupt(pin) — do not hardcode interrupt numbers.

attachInterrupt(digitalPinToInterrupt(btnPin), onBtn, FALLING);
Part

Tiny ISR + flag

volatile bool btnEvent = false;
void onBtn() { btnEvent = true; }   // OK — short
// Serial / delay / display.update  — BAD

void loop() {
  if (btnEvent) {
    btnEvent = false;
    // handle: count++, FSM, Serial...
  }
}

Counters in the ISR are fine for tallies; flags are better when loop must react once with heavier logic. Bounce may inflate counts today — expected.

Lab

attachInterrupt counter

18 min

Project M6-L02-AttachInterrupt: button→2 to GND. Print counts from loop only. Success: you can point to attachInterrupt + tiny ISR + loop printing the shared count.

Patterns

External interrupt counter

Pattern

INPUT_PULLUP → attachInterrupt(..., FALLING) → ISR bumps volatile data → loop does Serial/LEDs/FSM. Never Serial-from-ISR.

Check

Check yourself

  1. Which Uno pins support classic attachInterrupt?
    Model answer

    2 and 3 (INT0 / INT1).

  2. Why prefer digitalPinToInterrupt(pin)?
    Model answer

    Portable and readable — maps pin → interrupt across boards.

  3. List two things that must not appear inside an ISR.
    Model answer

    Serial.print, delay, slow display/I²C, long loops.

  4. For INPUT_PULLUP + button to GND, which edge matches “press started”?

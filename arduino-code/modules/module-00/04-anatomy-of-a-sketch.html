Anatomy of a sketch

setup() once, loop() forever — comments, pinMode discipline, and tracing a sketch by hand.

About 30 minutes. Reuse your Lesson 0.3 LED circuit.

Start here

Learning outcomes

  1. Identify setup(), loop(), and comments in any beginner sketch.
  2. Explain why pinMode belongs in setup, not repeatedly in loop.
  3. Read a short sketch top-to-bottom and predict whether an LED stays on, stays off, or will soon blink.
Concept

Two special functions

Concept

Every classic Arduino sketch has two special functions the board calls for you: setup() once at start, then loop() over and over forever. You do not call them yourself — the Arduino runtime does.

void setup() {
}

void loop() {
}

Names are case-sensitive. If you rename loop to Loop, the sketch will not work as intended.

Part 1

Comments

// Single-line comment — the compiler ignores it.

/*
 * Multi-line comment.
 * Great for a sketch title and wiring notes.
 */

Good comments explain why or how to wire. Skip comments that only restate the code.

Part 2

What belongs where

10 min

In setup() — once: pinMode, Serial.begin (later), initial levels, calibration.

In loop() — forever: turn outputs on/off, read buttons, timers, sensors.

Rule of thumb

Configure in setup. Behave in loop. You can call pinMode every loop, but it is the wrong mental model.

Part 3

Trace a sketch by hand

8 min

Predict the LED:

const int ledPin = 13;
void setup() {
  pinMode(ledPin, OUTPUT);
  digitalWrite(ledPin, LOW);  // start off
}
void loop() { /* empty */ }

Prediction: LED stays off.

void setup() { pinMode(13, OUTPUT); }
void loop() { digitalWrite(13, HIGH); }

Prediction: LED turns on and stays on. Blinking needs both HIGH and LOW and time — Lesson 0.5.

Lab

Tinkercad practice

  1. Open your Lesson 0.3 circuit (or duplicate as M0-L04-Anatomy).
  2. Paste the starter; Start Simulation — LED stays on.
  3. Change HIGH to LOW in setup — LED stays off.
  4. Move digitalWrite(..., HIGH) into loop — still on.

Starter sketch

const int ledPin = 13;

void setup() {
  pinMode(ledPin, OUTPUT);
  digitalWrite(ledPin, HIGH);  // start ON
}

void loop() {
  // Behavior belongs here — empty for exploration
}
Patterns

Configure once, run forever

Pattern

setup = stage lighting and props. loop = the play that repeats. Mixing them creates confusing bugs later.

Check

Check yourself

  1. How many times does setup() run after you start simulation?
  2. How many times does loop() run?
  3. Where should pinMode(ledPin, OUTPUT) go, and why?
    Model answer

    In setup — it is one-time configuration.

  4. What do // and /* */ do to the compiler?
    Model answer

    Mark comments; ignored when compiling.

Build: Custom blink signature

Module 0 project spine: design a personal blink pattern, document pin and resistor, and prove it in simulation.

About 45 minutes. This is the Module 0 build that ends the spine.

Start here

Learning outcomes

  1. Design a blink pattern that encodes your initials or a Morse letter.
  2. Implement it with digitalWrite and delay, using named pin and timing constants.
  3. Document pin, resistor, and meaning in the sketch header so another learner could rebuild it.
Brief

Project spine build

Done looks like

Someone watching the LED can tell your pattern repeats; someone reading the file knows how to wire it.

  1. A recognizable personal pattern (Morse initials, invented rhythm, or SOS).
  2. A named pin constant (not only bare 13).
  3. Comments state pin, resistor value, and what the pattern means.
  4. Runs in Tinkercad (or hardware) without compile errors.
Part 1

Pick a pattern

10 min

Option A — Morse initial

LetterMorseRhythm
A· −short, long
E·single short
S· · ·three shorts
O− − −three longs
T−single long

Option B — Free rhythm: write it in words first, e.g. ON 200, OFF 200, ON 600, OFF 1000 → repeat.

Choose any free digital pin (e.g. 8 or 13) and 220 Ω. Move the wire to match. Name the circuit M0-L06-BlinkSignature.

Part 2

Build and test

20 min
Your pin  →  220 Ω  →  LED anode  →  LED cathode  →  GND
  1. Start with one dot — confirm the LED works.
  2. Add the full letter or rhythm.
  3. Add a long pause between repeats so the pattern is readable.
  4. Only then polish the header comments.

Starter — Morse “S”

/*
 * Lesson 0.6 — Custom blink signature STARTER
 * Student: (your name)
 * Pattern meaning: Morse "S" (three short blinks)
 * Pin: 13 · Resistor: 220 ohm
 * Wiring: pin 13 → 220Ω → LED → GND
 */

const int ledPin = 13;
const int dotMs = 200;
const int gapMs = 200;
const int letterGapMs = 1000;

void setup() {
  pinMode(ledPin, OUTPUT);
}

void loop() {
  digitalWrite(ledPin, HIGH); delay(dotMs);
  digitalWrite(ledPin, LOW);  delay(gapMs);
  digitalWrite(ledPin, HIGH); delay(dotMs);
  digitalWrite(ledPin, LOW);  delay(gapMs);
  digitalWrite(ledPin, HIGH); delay(dotMs);
  digitalWrite(ledPin, LOW);
  delay(letterGapMs);
}

Complete example — Morse “A T” (personalize this)

const int ledPin = 8;
const int dotMs = 200;
const int dashMs = 600;
const int symbolGapMs = 200;
const int letterGapMs = 600;
const int wordGapMs = 1500;

void onFor(int ms) {
  digitalWrite(ledPin, HIGH);
  delay(ms);
  digitalWrite(ledPin, LOW);
}

void loop() {
  onFor(dotMs); delay(symbolGapMs); onFor(dashMs); // A
  delay(letterGapMs);
  onFor(dashMs); // T
  delay(wordGapMs);
}

Change the header, pin, and sequence so they are yours, not the example’s.

Deliverable

Checklist

  • LED pattern repeats clearly in simulation (or on hardware)
  • const int used for the LED pin
  • Timing uses named constants or clearly commented delays
  • Header lists: student name, pattern meaning, pin, resistor, wiring
  • Pin in code matches the wire in the circuit
Patterns

Document at the top

Pattern

Document at the top. Wiring notes in the header are part of the deliverable. Name your timings — dotMs, dashMs, gapMs beat mystery numbers.

Check

Check yourself

  1. If a friend opens only your .ino file, can they rebuild the circuit from the header alone?
    Model answer

    That is the goal — yes if you documented pin + resistor + topology.

  2. What must you change in two places when you move from pin 13 to pin 8?
    Model answer

    The ledPin constant (code) and the physical/sim wire.

  3. Why is a long letterGapMs / wordGapMs useful?
    Model answer

    So a human can see where the pattern starts and ends.

  4. Is using delay “wrong” for this Module 0 build?

Arduino IDE tour

Install Arduino IDE 2.x (or the Web Editor), learn Verify vs Upload, and see how Tinkercad’s Code panel speaks the same language.

About 30 minutes. Parallel / optional for Module 0 — you can finish 0.1 → 0.3 → 0.4 → 0.5 → 0.6 in Tinkercad only.

Start here

Learning outcomes

You can finish Module 0 in Tinkercad only

This IDE tour is parallel / optional until you want hardware or Module 7. If install stalls, skip ahead to Lesson 0.3 and come back. See Getting started.

  1. Install Arduino IDE 2.x or open the Arduino Web Editor, and create a new sketch.
  2. Distinguish Verify (compile/check) from Upload (send to a board).
  3. Find the Serial Monitor button and know when you will need it (Module 1+).
  4. Know how Tinkercad’s Code panel relates to the same sketch language.

Tools

  • Arduino IDE 2.x (optional now) — write, verify, and later upload
  • or Arduino Web Editor if install is blocked
  • Tinkercad — same C++-style language for Module 0 labs
  • USB board (optional) — only if you want a real Upload today

Dual path: Prefer Tinkercad first for Module 0 success. Install the IDE when you can (or before hardware / Module 7). Verify-before-Upload habits still matter.

Concept

The IDE is your workshop

Concept

Verify asks “Does this sketch compile?” Upload asks “Put it on the connected board.” In Tinkercad, Start Simulation is closer to Upload: it runs the sketch against the circuit. Always Verify (or fix red errors) before you hunt wiring bugs.

Part 1

Install Arduino IDE 2.x (when ready)

10 min
  1. Visit the official Arduino software download page and get IDE 2.x for your OS.
  2. Install with default options. On Windows, allow USB driver installation if prompted.
  3. Open the IDE. You should see a blank sketch with two empty functions: setup() and loop().

If your school computer blocks installs, use the Arduino Web Editor or stay in Tinkercad Code for Module 0 and install later before Module 7.

Part 3

Create, save, and Verify

8 min
  1. File → New Sketch (or use the empty one that opened).
  2. File → Save and name it Module0_IdeTour.
  3. Notice the folder: Arduino saves Module0_IdeTour/Module0_IdeTour.ino. The folder name and .ino name must match.

Paste the starter sketch below, then click Verify.

Success: “Done compiling” with no red errors. Failure: red text — read the first error; fix that before the rest.

Part 4

Verify vs Upload

5 min
Write code  →  Verify (compile)  →  Upload (to hardware)
                  ↑
           Fix errors here first
ActionNeeds a board?Purpose
VerifyNoCatch typos and syntax mistakes
UploadYes (USB + correct Port)Run on real hardware
Tinkercad Start SimulationNoRun against a virtual circuit

If Upload fails with “port not found,” you are not broken as a programmer — cable, drivers, or Port menu need attention. Module 7 covers hardware graduation in depth.

Part 5

How this maps to Tinkercad

  1. Open a circuit → Code panel → choose Text mode (not only Blocks).
  2. You write the same style of Arduino C++ (setup, loop, pinMode, …).
  3. There is no separate Upload — Start Simulation runs it.

Habit: Prefer Text mode for this course so skills transfer straight to the IDE.

Optional

Hardware smoke test

If you have an Uno and USB cable:

  1. Connect the board.
  2. Tools → Board → Arduino Uno.
  3. Tools → Port → select the new COM/tty port.
  4. File → Examples → 01.Basics → Blink.
  5. Click Upload. Pin 13’s on-board LED should blink.

If that works, you have completed a full write → verify → upload loop. If not, continue with Tinkercad; we will debug hardware carefully later.

Patterns

Verify early

Pattern

Verify early, verify often. Do not change ten lines and then Upload. Change a little, Verify, then proceed.

Starter sketch

Check

Check yourself

  1. Does Verify require a USB cable?
  2. What must match when you save a sketch: folder name or only the title in the window?
    Model answer

    The sketch folder name and the .ino filename should match.

  3. In Tinkercad, which button is the closest cousin of Upload?
  4. Why might Upload fail even when Verify succeeds?
    Model answer

    Wrong or missing Port, bad cable, wrong board selected, or drivers — not necessarily bad code.

Stretch (optional)

In the IDE, open File → Examples → 01.Basics → Blink. Read it without uploading. In a comment at the top, write what you think delay(1000) does. You will confirm in Lesson 0.5.
